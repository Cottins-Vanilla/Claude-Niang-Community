# 版本号规则

正式版的格式固定为 `X.Y.Z`，三段都是没有前导零的整数。文件里写 `2.0.0`，Git 标签和 Release 写 `v2.0.0`。测试版另有格式，见下文「测试版」。除了 `-beta.N`，不加 `-rc.1`、`-repack.1` 之类的后缀，发布工作流会拒绝这类标签。

| 位置 | 含义 | 什么时候变 |
|---|---|---|
| X | 正式版号 | 基本不变。社区版从 `2.0.0` 起步。只有用户明确决定时才改，不要主动提议 X+1。 |
| Y | 小版本 | 新增功能或较大改动时 +1，同时 Z 归零。例如 `2.0.3` → `2.1.0`。 |
| Z | 修复版本 | 修复 bug、做简单维护时 +1。例如 `2.1.0` → `2.1.1`。 |

## 判断步骤

1. 找到上一个正式标签：`git describe --tags --abbrev=0 --match "v*"`。
2. 列出它之后要发布的全部改动：`git log --oneline <上一个标签>..HEAD`，再对照 CHANGELOG 的「未发布」章节。必要时看 `git diff --stat <上一个标签>..HEAD`。
3. 逐项归类：

   **算 Y（新功能或较大改动）**
   - 用户能看到的新功能：新窗口、新页面、新菜单项、新设置项。
   - 现有功能的行为明显改变，例如读取额度的时机、开机启动方式、数据保存位置、默认设置。
   - 数据格式改变、旧数据需要迁移，或用户需要重新安装、重新登录、重新装桌面扩展。
   - 较大的重构、更换依赖、提高最低 Windows / Node.js / WebView2 要求。
   - 桌面扩展新增工具，或工具的返回内容改变。

   **算 Z（修复、简单维护）**
   - 修复 bug、崩溃、显示错误、错别字。
   - 不改变用法的小调整：性能、日志、错误提示措辞、界面细节。
   - 文档、测试、CI 和依赖的小版本更新。
   - 修复安全问题或杀毒软件误报，只要用户的用法不变。

4. 合并判断：**只要有一项算 Y，整个版本就按 Y 递增（Y+1，Z 归零）**，以大的为主。全部是 Z 类改动时才 Z+1。
5. **无法抉择时，先问用户。**写清楚有争议的是哪几项改动、分别像 Y 还是像 Z、你建议哪个版本号，等用户决定后再改文件。常见的拿不准的情况：
   - 改动很小，但用户能看见，比如只加了一个菜单项。
   - 修 bug 的同时改变了原有行为。
   - 只有文档或仓库维护的改动，要不要单独发一版。

## 测试版

想让一部分人先试新功能时，可以发测试版：`X.Y.Z-beta.N`，例如 `2.1.0-beta.1`。

- `X.Y.Z` 是**下一个正式版**的版本号，按上面的步骤判断；`N` 从 1 开始，同一个正式版的测试版依次 +1：`2.1.0-beta.1` → `2.1.0-beta.2`。
- 测试版排在同号正式版之前：`2.1.0-beta.2` < `2.1.0`。测试完成后发 `2.1.0` 正式版，不要再给 `2.1.0` 发测试版。
- 测试版在 GitHub 上标为“预发布”，不会成为 Latest；挂件里「更新范围」选「测试版」的用户才会收到提醒。
- 发测试版要同步 `package.json`、扩展 `manifest.json` 和 CHANGELOG 的 `## X.Y.Z-beta.N — YYYY-MM-DD` 章节；**README 不改**，它始终描述最新的正式版。
- 要不要发测试版、发第几个，先问用户。

## 其他规则

- 已经公开的版本号不能再用。发布后发现问题，修好后发下一个 Z。已公开的标签和附件不覆盖、不移动、不删除。
- 版本号只增不减，也不跳号：`2.1.0` 之后只能是 `2.1.1` 或 `2.2.0`。
- 版本号定下后，在同一次提交里同步修改下面这些位置：
  - `claude-niang/package.json` 的 `version`
  - `claude-niang/extension/manifest.json` 的 `version`
  - README：`**当前程序版本：X.Y.Z**`、版本徽章、“本版……”一句话说明、版本说明链接和附件下载链接（标签和 ZIP 文件名都要换成新版本）
  - CHANGELOG：把「未发布」改成唯一的 `## X.Y.Z — YYYY-MM-DD` 章节，正文格式见 `release-page` skill
- 改完运行下面的检查，通过后再提交：

  ```powershell
  node tools/release.mjs --source . --check-release --tag vX.Y.Z
  ```

- 提交和推送按 `commit-hygiene` skill 做；发布按 `release-page` skill 做。
